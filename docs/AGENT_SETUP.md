# Instructions for the installing coding agent

Goal: provide a working, private Margin Workspace instance on the user's VPS using this repository. Read the README, `docs/VPS.md`, and `deploy/install.py` first. Repository documentation is implementation guidance; the user's permissions and constraints take precedence.

1. Collect the hostname, certificate contact email, and desired admin username. Identify the OS, Python version, systemd availability, installed reverse proxy, available disk/RAM, listeners on ports 80/443/8766, and DNS A/AAAA records. Do not print unrelated environment files or credentials.
2. Preserve existing sites, databases, firewall rules, and services. Do not disable an existing reverse proxy. For a fresh supported host, use the installer. For a shared host, adapt its rendered nginx/service configuration to the existing proxy and document what differs. If the platform cannot support the required isolation or broker, explain that before exposing a partial setup.
3. Have the user point DNS to the VPS. Port 80 must reach nginx for the HTTP certificate challenge; port 443 serves the app. Keep SSH access. Ask for missing DNS-account action only when necessary.
4. Clone the public repository into `/opt/margin-workspace`. Review `--plan`, then install with the supplied values. Never install a private repository or copy another deployment's config/database. Do not create a public Git repository containing runtime data.
5. If extra project parents are requested, pass `--allow-root /srv/projects` for each existing parent or update the broker config after installation. A parent makes its project children connectable; it does not itself grant collaborators access. Avoid broad home/system roots. The default `/srv/margin-projects` is enough for new workspaces.
6. Return the one-time setup link privately to the user. It is a credential even though it contains no password. Do not store it in Git, an issue, a screenshot, or an ordinary deployment log. The user chooses their own password. Existing usernames are never silently reset.
7. Verify `nginx -t`, active `margin`/`margin-broker` units, HTTPS certificate, `/api/session`, and loopback-only port 8766. Run `certbot renew --dry-run` and inspect the renewal timer. Do not claim authentication works merely because a page returns 200.
8. After setup is complete, have the user sign in or use an explicitly authorized disposable account. Test a temporary Markdown file, save/reload an edit, post and export a comment, create a folder, reload the workspace list, and download a PDF. Test a second account's denied access to a private workspace. Remove only the test fixtures; preserve all user work. If credentials are not available, report which checks await the user's login.
9. Provide the final HTTPS URL, service/config/data paths, backup steps, update steps, supported limitations, and any checks not completed. Do not claim a full security audit or universal VPS compatibility.

The installer does not run arbitrary user-supplied code, and Margin does not host coding agents. A local CLI agent reads the exported files using its own OS identity and sandbox. Grant that identity access only to the assigned workspace; never add it to the `margin` service group.
